Completed the Specialty AI Architecture

During repeated runtime verification of the Knowledge Foundation, it became clear that concentrating entity extraction, relation generation, knowledge generation, and update decisions into a single Knowledge Structuring AI caused the prompt to become excessively large. As a result, the LLM increasingly prioritized rules and database schemas over the actual evidence. Various improvements, including schema filtering with SchemaSelector, prompt refinements, and JSON structure redesign, were introduced, but they did not fundamentally solve the problem.

To address this, the architecture was redesigned from the ground up. The monolithic AI was replaced with specialized AIs dedicated to individual entity domains such as User, Company, Project, ParentTask, ChildTask, AI, Document, and Code. These specialized AIs are connected through a shared execution pipeline consisting of the GenericCandidateBuilder, CandidateValidator, Decision Pipeline, and Knowledge Repository.

The role of the LLM was fundamentally redefined. Instead of generating complete entities, its responsibility is now limited to extracting values from evidence. Those extracted values are assembled into common templates by the application, while validation, decision making, and persistence are handled through a deterministic shared runtime. This approach minimizes probabilistic output from the LLM while allowing the application to guarantee consistent entity structures and persistence behavior.

As a result, every Specialty AI now runs on the same shared runtime, significantly reducing prompt size while improving stability, maintainability, and scalability. New specialties can now be added by providing only a prompt and entity definition.

The Knowledge Foundation has evolved from a monolithic AI architecture into a specialized AI architecture with a clear separation of responsibilities between the LLM and the application. The LLM is dedicated to extracting values from evidence, while the shared runtime assembles those values into common templates and performs validation, decision making, and persistence. This architecture provides a highly reproducible runtime that is no longer dependent on probabilistic LLM outputs. Because every Specialty AI shares the same execution foundation, new AI domains can be integrated simply by adding a prompt and an entity definition. As a result, the architecture has evolved into the extensible knowledge foundation at the core of the Knowledge OS, designed to support continuous feature expansion and future growth with high maintainability and scalability.
